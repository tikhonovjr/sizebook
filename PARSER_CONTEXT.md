## ГЛАВНАЯ НАХОДКА: Firecrawl умеет геолокацию

```js
// Firecrawl /v1/scrape принимает:
{
  url,
  formats: ['html'],
  waitFor: 6000,
  location: { country: 'RU' },   // ← рендер с РОССИЙСКОГО резидентного IP
  proxy: 'stealth'                // ← премиум-обход антибота (Ozon не берёт)
}
```

`location: { country: 'RU' }` — это то, что заменило собой всю затею с РФ-прокси.
Firecrawl рендерит страницу с российского резидентного IP, и цена оказывается прямо в HTML.

`parseViaFirecrawl(url, { waitFor, country, proxy })` — сигнатура обновлена, принимает оба параметра.

## Wildberries — как устроено сейчас

**title + image:** basket CDN (`basket-XX.wbbasket.ru/.../info/ru/card.json`).
Умный скан: сначала пробуем предсказанный по таблице basket, если промах — параллельно ±20 вокруг него.
Раньше было 60 слепых параллельных запросов; стало вдвое быстрее.

**price:** Firecrawl с `location: { country: 'RU' }`, цена парсится из отрендеренного HTML.

**Важно — запросы идут ПАРАЛЛЕЛЬНО:**
```js
// промис цены стартует ДО basket scan, await — уже после
const pricePromise = parseViaFirecrawl(url, { waitFor: 6000, country: 'RU' })...
// ... basket scan ...
const price = await pricePromise;
```
Без этого время складывалось (15+ с), с этим — 5.8 с.

В `_steps` отдаётся `price_source`: `firecrawl_ru` | `none`.

## Ozon — ЗАКРЫТ, нужен капча-солвер

Финальная причина: **страница «Antibot Captcha», HTTP 403**.

### Что проверено и НЕ работает

| Способ | Результат |
|---|---|
| прямой fetch (с прокси и без) | 403 после антибот-редиректа `?__rr=1` |
| `fetchWithCookies` (cookie-цепочка, 25 редиректов) | 403 на финальном URL с `__rr=1` |
| `composer-api.bx` / `entrypoint-api.bx` | 403 |
| мобильный API `api.ozon.ru` + `x-o3-app-name` | 403 |
| домены `ozon.by`, `ozon.kz` | то же самое |
| Playwright с РФ-прокси | пустая страница, 8 с впустую |
| Playwright без прокси | пустая страница |
| Firecrawl plain | заглушка «Похоже, нет соединения» |
| Firecrawl `location:RU`, waitFor 20 с | заглушка, 403 |
| Firecrawl `proxy:stealth` + `location:RU`, waitFor 12/25 с | **«Antibot Captcha», 403** |

`redirect count exceeded` в ранних пробах был ложным следом — это голый `fetch` без хранения куки,
а не блокировка. С `fetchWithCookies` цепочка доходит, но упирается в 403.

### Текущее поведение в коде

`parseOzon()` возвращает пустой результат **за 0 мс** с пометкой
`{ step: 'skipped', reason: 'antibot_captcha_requires_solver' }`.
Раньше тратил 8–20 с на заведомо мёртвый каскад.

### Единственный оставшийся путь

Внешний сервис с обходом антибота/капчи: Zyte, ScrapingBee, ScraperAPI.
**Перед оплатой — прогнать их бесплатный триал через probe-эндпоинт и убедиться, что работает.**

## Спортмастер — ЗАКРЫТ, Qrator-фингерпринтинг

Финальная причина: **HTTP 401 + «Ваши действия признаны автоматическими»**.

### Что проверено и НЕ работает

| Способ | Результат |
|---|---|
| прямой fetch | 401 |
| cookie-цепочка (главная → товар) | 401, **главная страница тоже 401** |
| AJAX-заголовки `X-Requested-With: XMLHttpRequest` | 401 |
| внутренние API (`/api/product/`, `/product/api/product/` и др.) | 401 / 403 с `incidentId` (признак Qrator) |
| Playwright без прокси | 401, в body — «Ваши действия признаны автоматическими» |
| Firecrawl plain / `location:RU` / `proxy:stealth` | 401 |
| Firecrawl с `actions` (wait + scroll) | 401 |
| **ruFetch через РФ-прокси Timeweb** | **401** |
| **Playwright + РФ-прокси Timeweb** | **401** |

**Ключевой вывод:** российский IP НЕ помогает. Timeweb-прокси даёт ровно тот же 401,
что и Railway из-за рубежа. Блокировка по фингерпринту (TLS-отпечаток, отсутствие
реальной браузерной истории), а не по географии.

Спортмастер сейчас в списке `BOT_PROTECTED` и тратит ~5 с на бесполезный каскад —
**стоит добавить быстрый выход, как у Ozon** (не сделано).

## Про РФ-прокси и VPS Timeweb

Куплен VPS Timeweb (Москва, ASN AS9123), поднят HTTP-прокси на tinyproxy, порт 3128.
`RU_PROXY_URL` задан в Railway Variables.

**В рабочем коде прокси сейчас не используется.** Итог по нему:

- WB price — решился без прокси, через Firecrawl `location:RU`
- WB `search.wb.ru` через прокси — 429 (Timeweb тоже датацентровый ASN)
- Ozon через прокси — 403 / fetch failed
- Спортмастер через прокси — 401

**Ошибка методики, которую не надо повторять:** сначала была принята гипотеза
«дело в IP» и куплен VPS, и только потом сделан перебор точек входа.
Правильный порядок — сначала probe всех эндпоинтов, потом выводы про инфраструктуру.

Варианты применения VPS: перенести на него сам SizeBook вместо Railway.

**Важно про socks5:** `undici.ProxyAgent` НЕ поддерживает `socks5://` —
при таком `RU_PROXY_URL` приложение падает при старте. Только `http://`.

Ещё грабли tinyproxy: по умолчанию в конфиге `Allow ::1` — внешние подключения
блокируются, нужно дописать `Allow 0.0.0.0/0`.

## Инфраструктура тестирования (GitHub Actions)

Построен автономный цикл: коммит → Railway деплой → Actions тестирует прод →
результаты коммитятся обратно в репо → читаются через GitHub Contents API.

**Зачем:** из облачной Claude-сессии Railway-домен заблокирован сетевым allowlist
(как и Azure blob с логами Actions, и `card.wb.ru`, и `wbbasket.ru`, и `12storeez.com`).
Единственный способ увидеть результат — чтобы Actions записал его файлом в репо.

### Файлы

- `.github/workflows/parse-test.yml` — основной цикл. Триггеры: `push` в main + `workflow_dispatch`.
  Ждёт `sleep 150-180` (деплой Railway), дёргает `/parse` по 4 магазинам, пишет `test_results.json`.
- `.github/workflows/deep-probe.yml` — ручной probe (`workflow_dispatch`), пишет `deep_probe.json`.
- `test_results.json` — scorecard последнего прогона.
- `deep_probe.json` — результаты последнего probe.

### Грабли Actions

- Шаг коммита падает при параллельных пушах — нужен retry с `git fetch` + `git reset --soft origin/main`.
- Логи Actions лежат на `productionresultssa18.blob.core.windows.net` — **заблокирован** из Claude-сессии.
  Поэтому всё, что нужно увидеть, должно писаться файлом в репо, а не в stdout.
- Сложные Python heredoc внутри YAML ломаются на интерполяции bash-переменных с JSON.
  Рабочий приём: curl пишет в файлы → Python читает файлы.
- У Railway таймаут HTTP-запроса ~5 мин: probe с 4+ вызовами Firecrawl подряд не успевает.
  Приём: один вариант на вызов через `?v=1..5`, цикл в workflow.
- Firecrawl free-план: ~12 запросов/мин, при превышении молча возвращает пустоту. Нужны паузы 8–20 с.

### Запуск probe вручную

```bash
WFID=355630324   # deep-probe.yml
curl -s -X POST -H "Authorization: token $TOKEN" \
  https://api.github.com/repos/tikhonovjr/sizebook/actions/workflows/$WFID/dispatches \
  -d '{"ref":"main"}'
```

Основной цикл: `WFID=355230665`.
